## 1. 接口基础规范

### 1.1 请求方式
| 操作 | HTTP方法 | 示例 |
|------|----------|------|
| 查询 | GET | `/api/v1/hazard-points/page` |
| 新增 | POST | `/api/v1/hazard-points` |
| 修改 | PUT | `/api/v1/hazard-points/{id}` |
| 删除 | DELETE | `/api/v1/hazard-points/{id}` |

### 1.2 路径规范
- 小写 + 中横线
- 按模块划分：`/api/v1/{module}/{resource}`

### 1.3 公共请求头
```http
Authorization: Bearer {token}
Content-Type: application/json
```

### 1.4 统一返回格式
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {},
  "timestamp": 1735689213000
}
```

### 1.5 状态码定义
| 状态码 | 含义 | 说明 |
|--------|------|------|
| 200 | 成功 | 操作成功 |
| 400 | 参数错误 | 请求参数校验失败 |
| 401 | 未登录 | Token过期或未登录 |
| 403 | 无权限 | 没有操作权限 |
| 404 | 不存在 | 资源不存在 |
| 500 | 服务器异常 | 系统内部错误 |
| 601 | 预警触发 | 告警触发 |
| 602 | 设备离线 | 设备离线通知 |

### 1.6 分页规范
**请求参数：**
- `pageNum`: 页码，默认1
- `pageSize`: 每页数量，默认10

**返回格式：**
```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "total": 128,
    "rows": [],
    "pageNum": 1,
    "pageSize": 10
  },
  "timestamp": 1735689213000
}
```

#### 2.6.4 SSE 实时订阅日志流
**路径：** `GET /api/v1/logs/stream`  
**描述：** 通过 SSE 订阅实时日志流，支持按日志类型筛选，并支持 `Last-Event-ID` 与 checkpoint 断线恢复

**请求头：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Authorization | string | 是 | Bearer Token |
| Accept | string | 是 | 固定为 `text/event-stream` |
| Last-Event-ID | string | 否 | 上次收到的事件 ID，断线重连时用于补发历史日志 |

**请求参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| types | string | 否 | 订阅日志类型，多个用逗号分隔，支持 `operation,auth,runtime` |
| subscriberKey | string | 否 | 订阅者唯一标识，用于 checkpoint 持久化恢复；不传则服务端按用户和类型自动生成 |

**SSE 事件说明：**
| 事件名 | 说明 |
|------|------|
| ready | 连接建立成功，`data.resumeEventId` 表示本次恢复起点 |
| operation | 实时操作日志事件 |
| auth | 实时认证日志事件 |
| runtime | 实时运行日志事件 |
| replay | 断线恢复补发的历史日志事件 |

**SSE 返回示例：**
```text
event:ready
retry:3000
data:{"resumeEventId":921779534004781002}

id:921779534004781003
event:replay
retry:3000
data:{"logType":"AUTH","authEventType":"UNAUTHORIZED","requestUri":"/api/v1/logs/runtime/page","resultStatus":"FAIL"}

id:921779534004781012
event:runtime
retry:3000
data:{"logType":"RUNTIME","level":"WARN","loggerName":"net.dreamlu.mica.net.server.task.ServerHeartbeatTask"}
```

#### 2.6.5 SSE 前端接入说明
**适用场景：** 日志大屏、管理后台日志监控页、告警联动组件

**连接规则：**
1. 前端使用浏览器原生 `EventSource` 或支持自定义 Header 的 SSE 客户端。
2. 浏览器原生 `EventSource` 无法直接追加 `Authorization` 请求头，建议通过同源鉴权、反向代理注入 Header，或使用支持 Header 的 SSE 封装库。
3. 建议为同一终端传入稳定的 `subscriberKey`，例如 `log-screen-admin`，以便服务端持久化 checkpoint。
4. 断线重连时，优先带上 `Last-Event-ID`；若未携带，服务端将尝试按 `subscriberKey` 读取 checkpoint 继续补发。

**前端示例（使用 fetch-event-source）：**
```ts
import { fetchEventSource } from '@microsoft/fetch-event-source'

const token = localStorage.getItem('token')
let lastEventId = ''

fetchEventSource('/api/v1/logs/stream?types=auth,runtime&subscriberKey=log-screen-admin', {
  headers: {
    Authorization: `Bearer ${token}`,
    Accept: 'text/event-stream',
    ...(lastEventId ? { 'Last-Event-ID': lastEventId } : {})
  },
  onopen(response) {
    if (!response.ok) {
      throw new Error(`SSE连接失败: ${response.status}`)
    }
  },
  onmessage(event) {
    if (event.id) {
      lastEventId = event.id
    }
    const payload = JSON.parse(event.data)
    if (event.event === 'ready') {
      console.log('SSE连接成功', payload.resumeEventId)
      return
    }
    if (event.event === 'replay') {
      console.log('补发日志', payload)
      return
    }
    console.log('实时日志', event.event, payload)
  },
  onerror(error) {
    console.error('SSE连接异常', error)
    throw error
  }
})
```
