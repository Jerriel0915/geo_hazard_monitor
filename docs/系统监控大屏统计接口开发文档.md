# 系统监控大屏统计接口 — 开发文档

**日期：** 2026-06-03
**版本：** v1.0
**作者：** 系统开发组

## 1. 调研结论

### 1.1 现状

前端全息看板（`web/src/views/holo-board/`）四个页面 100% 使用硬编码 mock 数据，未调用任何后端 API。后端两个 IoT 模块（
`zwei-iot` + `zwei-monitor`）提供纯 CRUD 接口，**零统计/聚合端点**。

### 1.2 数据位置

| 统计指标          | 存储位置                              | 说明                                                     |
|---------------|-----------------------------------|--------------------------------------------------------|
| 设备总数、设备状态分布   | **MySQL** `device` 表              | `status`（1正常/2故障/3离线），`run_status`（0未知/1运行/2停止）        |
| 传感器总数、传感器类型分布 | **MySQL** `device_sensor` 表       | `status`（0禁用/1启用），`monitor_type_id` 关联监测类型             |
| 隐患点总数、隐患点增长趋势 | **MySQL** `hazard_point` 表        | `status`（1监测中/2停测/3完结），`create_time`                   |
| 监测类型总数        | **MySQL** `monitor_type` 表        | 直接 COUNT                                               |
| 视频设备总数、状态分布   | **MySQL** `video_device` 表        | `status`（0离线/1在线/2故障）                                  |
| 设备-隐患点绑定关系    | **MySQL** `device_hazard_point` 表 | 已有 `countByDeviceId`、`selectHazardPointIdsByDeviceIds` |
| 最新监测值         | **IoTDB**                         | 已有 `GET /api/v1/monitor-data/latest`                   |
| 设备在线率（活动检测）   | **混合**                            | MySQL 设备列表 + IoTDB 时间窗口查询检查是否有上报                       |
| 时序趋势数据        | **IoTDB**                         | 已有 `GET /api/v1/monitor-data/chart`                    |

### 1.3 是否需要新增数据库表？

**不需要。** 所有基础统计数据均来自现有表。唯一缺失的是"告警"领域，但这属于新业务模块，不在本次大屏统计接口范围内。`device`、
`device_sensor`、`hazard_point`、`monitor_type`、`video_device` 五张表已覆盖全部需求。

### 1.4 是否需要引入新依赖？

**不需要。** 仅需新增 MyBatis 查询 SQL（GROUP BY + COUNT），全部为现有技术栈内实现。

## 2. 接口设计

所有新增接口归属 `zwei-monitor` 模块，部署在 `/api/v1/monitor/dashboard/` 路径下。

### 2.2 设备在线率（MySQL 状态字段直查）

**路径：** `GET /api/v1/monitor/dashboard/device-online-rate`

**说明：** 直接查询 MySQL `device` 表的 `run_status` / `status` 字段统计设备在线情况。响应快，反映的是设备最后注册/鉴权时的状态，非实时上报状态。

**实现逻辑：** 从 MySQL `device` 表按 `run_status` 和 `status` 分组统计。

**返回结构：**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "total": 2363,
    "online": 2215,
    "offline": 141,
    "unknown": 7,
    "onlineRate": 93.74,
    "byType": [
      {
        "monitorTypeId": 1,
        "monitorTypeName": "表面水平位移",
        "total": 535,
        "online": 510,
        "offline": 24,
        "unknown": 1,
        "onlineRate": 95.33
      }
    ]
  },
  "timestamp": 1735689213000
}
```

### 2.3 设备活跃率（IoTDB 窗口检测）

**路径：** `GET /api/v1/monitor/dashboard/device-active-rate`

**说明：** 基于 IoTDB 最近时间窗口内的数据上报记录，判断设备是否"真正在发数据"。活跃率 = 窗口内有上报的设备数 /
总设备数。比在线率更准确反映设备实际工作状态。

**请求参数：**

| 参数            | 类型  | 必填 | 说明                                                 |
|---------------|-----|----|----------------------------------------------------|
| windowMinutes | int | 否  | 活跃检测窗口（分钟），默认 60。前端可分别传 360（6h）、720（12h）、1440（24h） |

**实现逻辑：**

1. 从 MySQL 查询所有设备（id, code, name, monitor_type_id）
2. 对每个设备，查询 IoTDB 最近 `windowMinutes` 分钟内是否有数据上报
3. 按监测类型分组汇总活跃/不活跃/总数

**返回结构：**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "windowMinutes": 60,
    "total": 2363,
    "active": 2140,
    "inactive": 223,
    "activeRate": 90.56,
    "byType": [
      {
        "monitorTypeId": 1,
        "monitorTypeName": "表面水平位移",
        "total": 535,
        "active": 510,
        "inactive": 25,
        "activeRate": 95.33
      }
    ]
  },
  "timestamp": 1735689213000
}
```

### 2.4 传感器在线率（MySQL 启用状态）

**路径：** `GET /api/v1/monitor/dashboard/sensor-online-rate`

**说明：** 直接查 MySQL `device_sensor.status`，统计启用/禁用分布。在线率 = 启用传感器数 / 总传感器数。

**返回结构：**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "total": 4520,
    "enabled": 4480,
    "disabled": 40,
    "onlineRate": 99.12,
    "byType": [
      { "monitorTypeId": 1, "monitorTypeName": "表面水平位移", "total": 800, "enabled": 795, "onlineRate": 99.38 }
    ]
  },
  "timestamp": 1735689213000
}
```

### 2.5 传感器活跃率（IoTDB 窗口检测）

**路径：** `GET /api/v1/monitor/dashboard/sensor-active-rate`

**说明：** 基于 IoTDB 时间窗口检测传感器是否有实际上报数据。活跃率 = 窗口内有上报的传感器数 / 总传感器数。这是最真实的传感器工作状态指标。

**请求参数：** 同 2.3 `windowMinutes`（默认 60）

**返回结构：** 同 2.3 格式，`active` / `inactive` / `activeRate` + `byType`。

### 2.6 隐患点增长趋势

**路径：** `GET /api/v1/monitor/dashboard/hazard-point-trend`

**说明：** 按月统计隐患点新增数量。

**请求参数：**

| 参数     | 类型  | 必填 | 说明         |
|--------|-----|----|------------|
| months | int | 否  | 回溯月数，默认 12 |

**返回结构：**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "months": ["2025-07", "2025-08", ..., "2026-06"],
    "counts": [5, 3, 8, 12, 7, 4, 6, 9, 11, 2, 5, 3],
    "cumulativeCounts": [5, 8, 16, 28, 35, 39, 45, 54, 65, 67, 72, 75]
  },
  "timestamp": 1735689213000
}
```

### 2.7 传感器按监测类型分布

**路径：** `GET /api/v1/monitor/dashboard/sensor-distribution`

**说明：** 按监测类型分组统计传感器数量分布，用于大屏金字塔图/饼图。

**返回结构：**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    { "monitorTypeId": 1, "monitorTypeName": "表面水平位移", "sensorCount": 800 },
    { "monitorTypeId": 2, "monitorTypeName": "倾角", "sensorCount": 720 }
  ],
  "timestamp": 1735689213000
}
```

### 3.2 新增 Mapper 方法

所有新增方法返回简单数值或 `List<Map<String, Object>>`，不引入新实体。

```java
// DeviceMapper 新增
int countAll();
List<Map<String, Object>> countByStatus();  // GROUP BY status
List<Map<String, Object>> countByRunStatus(); // GROUP BY run_status

// DeviceSensorMapper 新增
int countAll();
List<Map<String, Object>> countByStatus();  // GROUP BY status
List<Map<String, Object>> countByMonitorType(); // GROUP BY monitor_type_id

// HazardPointMapper 新增
int countAll();
List<Map<String, Object>> countByStatus(); // GROUP BY status
List<Map<String, Object>> countByMonth(int months); // GROUP BY DATE_FORMAT(create_time, '%Y-%m')

// VideoDeviceMapper 新增
int countAll();
List<Map<String, Object>> countByStatus(); // GROUP BY status

// MonitorTypeMapper 新增
int countAll();
```

### 3.3 依赖关系

```
DashboardStatController (zwei-monitor)
  ├── DashboardStatService (zwei-monitor) — 聚合逻辑
  │     ├── DeviceMapper (zwei-iot) — MySQL 设备统计
  │     ├── DeviceSensorMapper (zwei-iot) — MySQL 传感器统计
  │     ├── HazardPointMapper (zwei-iot) — MySQL 隐患点统计
  │     ├── MonitorTypeMapper (zwei-iot) — MySQL 监测类型统计
  │     ├── VideoDeviceMapper (zwei-iot) — MySQL 视频设备统计
  │     └── IotdbTimeSeriesService (zwei-iot) — IoTDB 活动检测
  └── 前端 API (web/src/api/monitor.ts) — 类型 + 函数
```

不需要新增模块间依赖 — `zwei-monitor` 已依赖 `zwei-iot`。

### 3.4 告警模块说明

告警大屏数据（Alarm.vue）依赖的告警统计（告警等级分布、告警趋势、告警事件列表等）**不在此次范围内**
，因为后端尚无告警领域模型。告警模块需单独立项开发，涉及：

- 新 MySQL 表：`alarm_record`、`alarm_criteria`、`alarm_notification`
- 新 Maven 模块：`zwei-alarm`
- 告警引擎与 MQTT 消息联动的业务逻辑

本次仅实现基于现有设备/传感器/隐患点/监测类型数据的基础统计指标。

## 4. 复杂度评估

| 阶段                        | 内容                                     | 预估时间          |
|---------------------------|----------------------------------------|---------------|
| Mapper 层（6 个接口 + 6 个 XML） | 新增 COUNT / GROUP BY SQL                | 40 min        |
| Service 层                 | DashboardStatService 聚合逻辑 + IoTDB 窗口检测 | 40 min        |
| Controller 层              | 7 个端点                                  | 25 min        |
| 前端 API 层                  | monitor.ts 类型 + 函数                     | 15 min        |
| 编译验证                      | 全量编译 + 修复                              | 15 min        |
| **总计**                    |                                        | **约 2.25 小时** |

**复杂度：MEDIUM** — 大量 SQL 新增但逻辑简单，无架构变更，无新依赖。
