# 通用 JSON 报文解析器

新增通用 MQTT JSON 报文标准化解析逻辑，支持单值、多值和历史兼容结构，统一输出标准化时序点。

## 报文结构分类

报文结构分为两类：

- **标准结构**：包含 `version` 或 `data` 节点，常见于新版设备协议
- **历史兼容结构**：以设备ID为键的嵌套对象，常见于早期设备或特定厂商协议

## 解析流程

1. 判断是否支持该主题（`sourceType == "sys"`）
2. 解析原始报文为 JSON 对象
3. 根据报文结构选择对应解析路径
4. 将各种格式的数据统一转换为 `StandardMeasurementPoint` 列表

## 支持的报文格式示例

### 1. 标准单值（数值）

`value` 为 `Number`，默认映射到 `attrCode="value"` 的属性：

```json
{
  "version": "1.0",
  "sensorNo": "1",
  "timestamp": 1716979200000,
  "data": {
    "time": 1716979200000,
    "value": 25.5
  }
}
```

### 2. 标准单值（字符串）

`value` 为不含逗号的数字字符串，同数值处理：

```json
{
  "version": "1.0",
  "sensorNo": "1",
  "data": {
    "time": 1716979200000,
    "value": "25.5"
  }
}
```

### 3. 标准多值（对象）

`value` 为 JSON 对象，每个 key 对应一个传感器属性 `attrCode`：

```json
{
  "version": "1.0",
  "sensorNo": "1",
  "timestamp": 1716979200000,
  "data": {
    "time": 1716979200000,
    "value": {
      "gpsTotalX": 1.2,
      "gpsTotalY": 2.3
    }
  }
}
```

### 4. 标准多值（CSV）

`value` 为逗号分隔字符串，按顺序与传感器属性（id 升序）对齐：

```json
{
  "version": "1.0",
  "sensorNo": "1",
  "timestamp": 1716979200000,
  "data": {
    "time": 1716979200000,
    "value": "25.5,50"
  }
}
```

### 5. 批量历史报文

`data` 节点直接为以时间戳为键的映射对象：

```json
{
  "version": "1.0",
  "sensorNo": "1",
  "timestamp": 1716979300000,
  "data": {
    "1716979200000": 25.5,
    "1716979250000": 25.8
  }
}
```

### 6. 历史兼容报文

以 `deviceId` 为顶层键的嵌套对象，仅处理键以 `_sensorNo` 结尾的测点：

```json
{
  "101": {
    "temperature_01": {
      "1716979200000": 25.5
    },
    "humidity_01": {
      "1716979200000": 60.2
    }
  }
}
```
