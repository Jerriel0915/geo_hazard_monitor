# 基础命名规范（强制）

## 库名

小写 + 下划线，见名知意
示例：geo\_hazard\_monitor

## 表名

小写 + 下划线，业务模块前缀，复数优先
示例：user\_users、hazard\_disasters、monitor\_sensors

## 字段名

小写 + 下划线，禁止使用关键字
示例：disaster\_type、monitor\_value、warning\_level

## 约束名

表名\_字段名\_约束类型
示例：pk\_sensor\_id、idx\_disaster\_area\_code

# 字段设计规范

## 主键

所有业务表必须有主键，类型 BIGINT 自增或雪花算法，字段名统一 id

## 选基础字段（所有表必须包含）

- create\_time DATETIME 创建时间
- update\_time DATETIME 更新时间
- creator VARCHAR (64) 创建人
- updater VARCHAR (64) 更新人
- del\_flag TINYINT 删除标记 0 - 正常 1 - 删除

## 数值类型

经纬度用 DECIMAL(10,6)，位移 / 雨量 / 含水率用 DECIMAL(12,2)

## 字符串

定长用 CHAR，变长用 VARCHAR，超长文本用 TEXT

## 状态字段

统一用 TINYINT，搭配注释枚举值

## 索引规范

- 主键必有聚簇索引
- 查询条件字段建普通索引
- 多条件联合查询建联合索引
- 禁止冗余索引、重复索引

# 数据库设计其他约束
 - 引擎：统一 InnoDB
 - 字符集：utf8mb4
 - 注释：表、字段必须加注释
 - 分表策略：监测数据量大，按天 / 月 + 灾害点分表
 - 禁止：存储过程、外键、触发器（业务逻辑在 Java 层实现）


# 总结
 - 数据库：统一命名、必备审计字段、核心 5 张业务表、禁止触发器 / 外键
 - 行业适配：监测数据高频写入采用分表 + 实时表，预警等级严格按蓝黄橙红定义
 - 可直接用于：需求评审、详细设计、代码开发、测试用例编写
