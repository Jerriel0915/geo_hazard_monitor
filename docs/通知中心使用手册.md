# 通知中心使用手册

> 面向所有登录用户。本文介绍顶部铃铛「通知中心」的事件/公告双 Tab 使用方式，
> 以及管理员如何配置短信、邮件通道参数。

---

## 1. 入口与布局

| 元素 | 位置 | 说明 |
|---|---|---|
| 铃铛图标 | 顶部导航栏右上角 | 角标显示未读总数（事件 + 公告合计） |
| 通知面板 | 点击铃铛后下拉 | 默认打开「事件」Tab，可切换至「公告」Tab |
| 事件 Tab | 默认 | 用户接收的告警/设备离线通知（最多 50 条） |
| 公告 Tab | 次选 | 系统发布的公告通知 |
| 全部已读 | 面板底部按钮 | 仅作用于当前 Tab |

铃铛角标每 30 秒自动刷新一次未读数；若保持页面打开，新通知通过 SSE 实时推入。

---

## 2. 事件 Tab — 接收哪些通知

事件 Tab 只展示与当前登录用户相关的两类系统通知：

| 来源 | 触发时机 | 示例标题 |
|---|---|---|
| 告警触发 | `AlarmTriggeredEvent` 命中分发规则，当前用户在收件人列表中 | `[告警] THRESHOLD` |
| 设备离线 | `DeviceOfflineEvent` 命中分发规则 | `[设备离线] client-xxx` |

> 用户能否收到某条事件通知，取决于**告警分发规则** (`/alarm/notification-setting`) 中是否将本用户加入收件人。
> 规则由具备 `alarm:dispatch:*` 权限的角色配置。

### 2.1 已读/未读

| 状态 | 触发条件 |
|---|---|
| 未读 | 通知创建后默认状态 |
| 已读 | 用户点击该条通知 → 后端 `POST /api/v1/alarm/notifications/{id}/read` 标记 |
| 全部已读 | 用户点击「全部已读」→ 后端 `POST /api/v1/alarm/notifications/read-all` 仅影响本人 |

> 同一条告警派发给多个用户时，每个用户都有独立的已读状态（按 `recipient_id` 隔离）。

### 2.2 点击通知跳转

点击事件 Tab 中的某条通知，前端会根据来源路由跳转：

| 通知 sourceType | 跳转目标 | 行为 |
|---|---|---|
| `alarm` | `/alarm/realtime?alarmId={sourceId}` | 自动打开该告警的详情对话框 |
| `offline` | `/basic/device?deviceId={sourceId}` | 自动打开该设备的详情对话框 |

跳转后会同时标记该通知为已读。

---

## 3. 公告 Tab

公告 Tab 数据源为 `/api/v1/system/notice/*`，由系统管理员在「系统管理 > 通知公告」模块发布。
点击公告跳转至 `/system/notice/detail/{id}` 详情页。

---

## 4. 管理员：通道参数配置

> 需要具备 `system:config:*` 权限。

进入「系统管理 > 系统设置 > 通知配置」分类，可配置以下 11 个参数：

### 4.1 短信（阿里云/腾讯云通用）

| 参数键 | 说明 |
|---|---|
| `notify.sms.access-key-id` | 服务商 AccessKeyId |
| `notify.sms.access-key-secret` | AccessKeySecret（密码框不回显，保存时若留空则跳过该字段，不覆盖已存在的密钥） |
| `notify.sms.sign-name` | 已审批的短信签名 |
| `notify.sms.template.alarm` | 告警短信模板编号 |
| `notify.sms.template.offline` | 设备离线短信模板编号 |

### 4.2 邮件（SMTP）

| 参数键 | 说明 |
|---|---|
| `notify.mail.host` | SMTP 服务器，如 `smtp.qiye.aliyun.com` |
| `notify.mail.port` | 端口，SSL 默认 465 |
| `notify.mail.username` | SMTP 登录账号（通常为发件邮箱） |
| `notify.mail.password` | SMTP 密码或授权码（密码框不回显） |
| `notify.mail.from` | 发件人地址 |
| `notify.mail.ssl` | 是否启用 SSL |

### 4.3 持久化机制

- 所有参数通过 `sys_config` 表保存（`configKey = notify.sms.*` / `notify.mail.*`）
- 读取：`GET /system/config/configKey/{key}`
- 保存：`PUT /system/config/configKey/{key}` body `{configValue: "..."}`
- 类型转换由前端自动处理（switch→`'true'/'false'`，number→字符串，其他原值）

### 4.4 启用条件

短信/邮件通道**仅在分发规则勾选了对应渠道**（`SMS` / `EMAIL`）时才会触发发送。
若通道未配置（如 `notify.sms.access-key-id` 为空），该条通知会落库为状态 `5` (CHANNEL_NOT_CONFIGURED)，
不会反复重试。

## 5. 后端 API 速查

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/alarm/notifications/recent?limit=10` | `alarm:notification:list` | 当前用户最近事件（默认 10，最多 100） |
| GET | `/api/v1/alarm/notifications/unread-count` | `alarm:notification:list` | 当前用户 SYSTEM 渠道未读数 |
| POST | `/api/v1/alarm/notifications/{id}/read` | `alarm:notification:read` | 标记单条已读（仅 owner 生效） |
| POST | `/api/v1/alarm/notifications/read-all` | `alarm:notification:read` | 当前用户全部已读 |
| GET | `/api/v1/system/notice/stream` | 登录即可 | 系统公告 SSE 流 |
| GET | `/api/v1/alarm/stream` | 登录即可 | 告警事件 SSE 流（按 userId 路由） |

## 6. 常见问题

**Q: 为什么我没收到告警通知？**
A: 检查链路：
1. 告警是否触发（看 `/alarm/realtime` 是否有记录）
2. 是否有匹配的分发规则（看 `/alarm/notification-setting`，规则需启用且 hazardPoint/alarmLevel 匹配）
3. 是否在收件人列表（规则详情中的"接收人"）
4. 用户状态是否为停用（`sys_user.status=1` 的用户不会收到通知）

**Q: 铃铛角标数字不对？**
A: 角标 = 事件 Tab 未读 + 公告 Tab 未读。如果只看事件 Tab，请以事件 Tab 内角标为准。
未读数每 30 秒刷新一次，刚标记已读后可能有最长 30 秒延迟。

**Q: 短信/邮件没发送但状态显示"已发送"？**
A: `已发送` 表示通知记录已落库 + 渠道分发已完成。若通道报错，状态会是 `发送失败 (3)`。
请到「系统监控 > 运行日志」查看 SMS/Email 通道的具体错误。

**Q: 同一告警收到多条相同通知？**
A: 通知按 `userId|channel` 去重，同一用户在同一渠道下只会收到一条。如果跨渠道（如 SYSTEM + SMS）
都配置了，则会分别收到两条，这是预期行为。
