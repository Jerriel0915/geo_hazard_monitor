# 监测模型重构与模块拆分 — 实施方案

**日期：** 2026-06-06
**版本：** v1.0
**状态：** 方案已确认，待执行

## 决策确认

| 决策项 | 确认结论 |
|--------|---------|
| 监测分类结构 | 平级 8 大类，不分层 |
| 新模块前缀 | `zwei-iot-` |
| 执行方式 | 分阶段，独立 PR |
| 废弃列处理 | 提供增量 DDL + 数据迁移 + 回滚脚本 + 清理脚本 |
| sensor_attribute 与 monitor_content 关系 | 快照副本模式（冗余字段 + monitor_content_id FK） |

## 一、目标架构总览

### 1.1 重构后的监测模型

```
monitor_category (监测大类 — 平级 8 类)
  │
  │ 1:N
  ▼
monitor_type (监测类型)
  │  [废弃] device_type — 不再使用
  │
  │ 1:N
  ▼
monitor_content (监测内容/指标定义)
  │  code, name, unit, indicator_type, range_min, range_max, icon
  │
  │ 1:N (通过 monitor_content_id FK + attr_code 快照)
  ▼
sensor_attribute (传感器属性实例)
  │  monitor_content_id → monitor_content.id  [NEW FK]
  │  attr_code, attr_name, unit  [快照副本，来自 monitor_content]
  │  initial_value, range_min, range_max  [实例化覆盖值]
  │  [废弃] indicator_type, indicator_type_name  [改为 JOIN 获取]
  │
  │ 写入 IoTDB
  ▼
root.geo_hazard.d{device_id}.s{sensor_no}.{attr_code}
```

### 1.2 重构后的模块拓扑

```
zwei-common (不变)
    │
    ├── zwei-iot-monitor (NEW)  — 监测字典: category + type + content
    │     └── 依赖: zwei-common
    │
    ├── zwei-iot-device (NEW)   — 设备全生命周期
    │     ├── 依赖: zwei-common, zwei-iot-monitor
    │     └── 对外接口: IDeviceAuthQueryService, IDeviceSensorQueryService, IDeviceQueryService
    │
    ├── zwei-iot-timeseries (NEW) — IoTDB 时序
    │     ├── 依赖: zwei-common, zwei-iot-monitor, zwei-iot-device (仅 Service 接口)
    │     └── 对外接口: ITimeSeriesWriteService
    │
    ├── zwei-iot-broker (NEW) — MQTT 鉴权与消息
    │     └── 依赖: zwei-common, zwei-iot-device (仅 Service 接口)
    │
    ├── zwei-iot-hazard (NEW) — 隐患点管理
    │     └── 依赖: zwei-common, zwei-iot-device (仅 Service 接口)
    │
    └── zwei-iot-video (NEW) — 视频设备
          └── 依赖: zwei-common
```

## 二、数据库变更脚本

### 2.1 DDL 增量脚本

```sql
-- ============================================================
-- V2.0_01_monitor_model_refactor.sql
-- 监测模型重构 — 增量 DDL
-- 执行前提: geo_hazard_monitor v1.9 schema
-- ============================================================

-- Step 1: 创建监测大类表
DROP TABLE IF EXISTS `monitor_category`;
CREATE TABLE `monitor_category`
(
    `id`          bigint       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `code`        varchar(100) NOT NULL COMMENT '大类编码，如 RAINFALL',
    `name`        varchar(200) NOT NULL COMMENT '大类名称，如 雨量',
    `icon`        varchar(200) DEFAULT NULL COMMENT '图标路径',
    `sort_order`  int          DEFAULT '0' COMMENT '排序号',
    `status`      tinyint      DEFAULT '1' COMMENT '状态: 0-禁用, 1-启用',
    `create_by`   varchar(64)  DEFAULT NULL COMMENT '创建者',
    `create_time` datetime     DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_by`   varchar(64)  DEFAULT NULL COMMENT '更新者',
    `update_time` datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `del_flag`    tinyint      DEFAULT '0' COMMENT '删除标记: 0-正常, 1-删除',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_monitor_category_code` (`code`),
    KEY `idx_monitor_category_status` (`status`),
    KEY `idx_monitor_category_del_flag` (`del_flag`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci COMMENT ='监测大类表';

-- Step 2: monitor_type 新增 category_id
ALTER TABLE `monitor_type`
    ADD COLUMN `category_id` bigint DEFAULT NULL COMMENT '监测大类ID' AFTER `code`,
    ADD KEY `idx_monitor_type_category` (`category_id`);

-- Step 3: sensor_attribute 新增 monitor_content_id
ALTER TABLE `sensor_attribute`
    ADD COLUMN `monitor_content_id` bigint DEFAULT NULL COMMENT '监测内容ID' AFTER `sensor_id`,
    ADD KEY `idx_sensor_attr_content` (`monitor_content_id`);
```

```sql
-- ============================================================
-- V2.0_02_monitor_model_data_migrate.sql
-- 监测模型重构 — 数据迁移
-- 执行前提: V2.0_01 已执行
-- ============================================================

-- Step 1: 预置 8 大监测类别
INSERT INTO `monitor_category` (`code`, `name`, `icon`, `sort_order`, `status`, `create_by`)
VALUES
    ('RAINFALL',     '雨量',   '/jc-icon/green/wj_green.png',    1, 1, 'system'),
    ('DISPLACEMENT', '位移',   '/jc-icon/green/jsd_green.png',   2, 1, 'system'),
    ('TEMPERATURE',  '温湿度', '/jc-icon/green/ky_green.png',    3, 1, 'system'),
    ('WATER_LEVEL',  '水位',   '/jc-icon/green/sg_green.png',    4, 1, 'system'),
    ('CRACK',        '裂缝',   '/jc-icon/green/jsd_green.png',   5, 1, 'system'),
    ('INCLINATION',  '倾斜',   '/jc-icon/green/nw_green.png',    6, 1, 'system'),
    ('SOIL_TEMP',    '地温',   '/jc-icon/green/gnss_green.png',  7, 1, 'system'),
    ('SOIL_MOISTURE','含水率', '/jc-icon/green/lf_green.png',    8, 1, 'system');

-- Step 2: 回填 monitor_type.category_id
-- 映射规则: monitor_type.code 前缀匹配 monitor_category.code
UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'RAINFALL')
WHERE `code` = 'JCLX001' AND `del_flag` = 0;

UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'DISPLACEMENT')
WHERE `code` = 'JCLX002' AND `del_flag` = 0;

UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'TEMPERATURE')
WHERE `code` = 'JCLX003' AND `del_flag` = 0;

UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'WATER_LEVEL')
WHERE `code` = 'JCLX004' AND `del_flag` = 0;

UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'CRACK')
WHERE `code` = 'JCLX005' AND `del_flag` = 0;

UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'INCLINATION')
WHERE `code` = 'JCLX006' AND `del_flag` = 0;

UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'SOIL_TEMP')
WHERE `code` = 'JCLX007' AND `del_flag` = 0;

UPDATE `monitor_type` SET `category_id` = (SELECT `id` FROM `monitor_category` WHERE `code` = 'SOIL_MOISTURE')
WHERE `code` = 'JCLX008' AND `del_flag` = 0;

-- Step 3: 回填 sensor_attribute.monitor_content_id
-- 通过 attr_code 与 monitor_content.code 匹配
UPDATE `sensor_attribute` sa
    JOIN `monitor_content` mc ON sa.`attr_code` = mc.`code`
SET sa.`monitor_content_id` = mc.`id`;

-- Step 4: 验证回填结果
SELECT 'monitor_type 未匹配 category_id 的记录数:' AS check_item,
       COUNT(*) AS cnt FROM `monitor_type` WHERE `category_id` IS NULL AND `del_flag` = 0
UNION ALL
SELECT 'sensor_attribute 未匹配 monitor_content_id 的记录数:',
       COUNT(*) FROM `sensor_attribute` sa WHERE sa.`monitor_content_id` IS NULL;
```

### 2.3 回滚脚本

```sql
-- ============================================================
-- V2.0_03_monitor_model_rollback.sql
-- 监测模型重构 — 回滚
-- 执行前提: V2.0_01 + V2.0_02 已执行
-- ============================================================

-- 注意: 此脚本将移除新增列和表。已写入的数据不会丢失（monitor_type/sensor_attribute 原始列未被修改）。
--       但 monitor_category 表数据将丢失。

ALTER TABLE `monitor_type` DROP COLUMN `category_id`;
ALTER TABLE `sensor_attribute` DROP COLUMN `monitor_content_id`;
DROP TABLE IF EXISTS `monitor_category`;
```

### 2.4 遗留列清理脚本（3 个月后执行）

```sql
-- ============================================================
-- V2.0_04_monitor_model_cleanup.sql
-- 监测模型重构 — 废弃列清理
-- 执行前提: 确认所有前端/后端代码已不再引用以下列
--           monitor_type.device_type
--           sensor_attribute.indicator_type
--           sensor_attribute.indicator_type_name
-- ============================================================

ALTER TABLE `monitor_type` DROP COLUMN `device_type`;
ALTER TABLE `sensor_attribute`
    DROP COLUMN `indicator_type`,
    DROP COLUMN `indicator_type_name`;
```

## 三、Java 代码变更清单

### 3.1 阶段 1: 监测模型重构（新增 + 修改，不删除）

#### A. 新增文件

| 文件 | 说明 |
|------|------|
| `monitor/domain/MonitorCategory.java` | 监测大类实体 |
| `monitor/mapper/MonitorCategoryMapper.java` | MyBatis Mapper 接口 |
| `monitor/mapper/MonitorCategoryMapper.xml` | MyBatis XML 映射 |
| `monitor/service/IMonitorCategoryService.java` | Service 接口 |

| `monitor/domain/dto/MonitorCategoryUpdateRequest.java` | 修改 DTO |

#### B. 修改文件

| 文件 | 修改内容 |
|------|---------|
| `MonitorType.java` | 新增 `categoryId`、`categoryName` 字段 |
| `MonitorTypeMapper.xml` | 查询 SQL 增加 category_id + JOIN category 表获取 name |
| `MonitorTypeCreateRequest.java` | 新增 `categoryId` 字段 |
| `MonitorTypeUpdateRequest.java` | 新增 `categoryId` 字段 |

| `SensorCreateRequest.java` / `SensorUpdateRequest.java` | attrList 中的 `indicatorType`/`indicatorTypeName` 标记为非必填（改为从 monitor_content 获取） |

### 3.2 阶段 2: 抽取 Service 接口（不移动文件）

#### A. 在 device 包中新增接口实现

| 文件 | 方法 | 调用方 |

| `IDeviceAuthQueryService` | `findByAuthUsername(String)` → Device 含 auth 字段 | broker |
| `IDeviceSensorQueryService` | `requireSensorMetadata(Long deviceId, String sensorNo)` → SensorMetadata | timeseries |
| `IDeviceQueryService` (增强) | 完善 `findBriefList()`, `findByIds()` 等方法 | hazardpoint |

#### B. 在 timeseries 包中新增接口实现

| 文件 | 方法 | 调用方 |
|------|------|--------|
| `ITimeSeriesWriteService` | `createSensorSchema(Long deviceId, String sensorNo, List<String> attrCodes)` | device |

#### C. 修改调用方

| 文件 | 修改内容 |
|------|---------|
| `MqttDeviceAuthService.java` | 将 `deviceMapper.selectByAuthUsername()` 改为 `IDeviceAuthQueryService.findByAuthUsername()` |
| `MonitorMetadataService.java` | 将 `deviceSensorMapper.selectSensorList()` + `sensorAttributeMapper.selectAttributeListBySensorId()` 改为 `IDeviceSensorQueryService.requireSensorMetadata()` |
| `MonitorIngestFacade.java` | 将 `metadataService.requireSensorMetadata()` 改为通过 `IDeviceSensorQueryService` |
| `DeviceSensorServiceImpl.java` | 将 `iotdbTimeSeriesService.createSensorSchema()` 改为 `ITimeSeriesWriteService.createSensorSchema()` |

### 3.3 阶段 3: 模块拆分

#### 模块创建顺序与内容

```
1. zwei-iot-monitor (无内部 IoT 依赖，先拆分)

4. zwei-iot-broker
   ├── 迁移: com.zwei.iot.broker.*  (全量)
   └── 依赖: zwei-iot-device (仅 Service 接口层)

5. zwei-iot-hazard
```
