## 2. 数据接入层

### 2.1 数据到达

```
MQTT PUBLISH sys/v1/{deviceCode}/{sensorNo}/updata
  → MqttServerMessageListener.onMessage()
  → MonitorIngestFacade.ingest(topic, payload, deviceId)
  → MonitorTopicParser → MonitorMetadataService → SysMonitorPayloadParser
  → StandardMeasurementPoint → Redis Stream (stream:monitor:ingest)
```

### 2.2 事件发布

**文件:** `MonitorIngestConsumerService.java`

```java
// IoTDB 写入成功后
iotdbTimeSeriesService.writePoints(List.of(point));

// 发布事件驱动告警引擎
applicationEventPublisher.publishEvent(new MonitorDataIngestedEvent(
    point.deviceId(), point.sensorId(), point.sensorNo(),
    point.attrCode(), point.value(), point.dataTime(), point.sourceType()
));
```

### 2.3 MonitorDataIngestedEvent 字段

| 字段         | 类型     | 说明                             |
|------------|--------|--------------------------------|
| deviceId   | Long   | 设备ID                           |
| sensorId   | Long   | 传感器ID                          |
| sensorNo   | String | MQTT 主题编号                      |
| attrCode   | String | 属性编码（如 "value", "temperature"） |
| value      | Double | 当前测量值                          |
| dataTime   | Long   | 数据时间戳 (epoch millis)           |
| sourceType | String | "sys" 或 "gb"                   |

## 3. 告警评估引擎

### 3.1 入口

**文件:** `AlarmEvaluationEngine.java`

```
@EventListener
onMonitorDataIngested(MonitorDataIngestedEvent event)
  → evaluate(event)
```

### 3.2 传感器→监测内容映射

```
event.attrCode (如 "value")
  → IDeviceSensorQueryService.requireSensorMetadata(deviceId, sensorNo)
    → SensorMetadata.attributes[]
      → SensorAttribute.monitorContentId  ← 匹配 attrCode
```

### 3.3 判据加载优先级

```
优先级1: 隐患点专属判据
  WHERE hazard_point_id = ? AND is_enabled = 1 AND del_flag = 0

优先级2: 监测类型兜底判据 (仅当优先级1未触发)
  1) monitorContentId → MonitorContentMapper → monitorTypeId
  2) WHERE monitor_type_id = ? AND hazard_point_id IS NULL AND is_enabled = 1
```

### 3.4 判据缓存架构

**文件:** `CriteriaCacheService.java`

```
┌─────────────────┐
│ L1: 本地 Map     │  ConcurrentHashMap, 0ms
│ key: REDIS_KEY   │
└────────┬────────┘
         │ miss
┌────────▼────────┐
│ L2: Redis        │  GET alarm:criteria:enabled, ~1ms, TTL 5min
└────────┬────────┘
         │ miss
┌────────▼────────┐
│ L3: MySQL        │  SELECT * FROM alarm_criteria WHERE is_enabled=1
└────────┬────────┘
         │
    refreshCache() → 写入 L1 + L2

判据变更 (insert/update/delete/toggle)
  → AlarmCriteriaServiceImpl
    → cacheService.refresh() → 清 L1 + 删 Redis key + 重载 L3
```

### 3.5 判据评估 (level_config)

**文件:** `CriteriaEvaluator.java`

#### 3.5.1 level_config 结构

```json
{
  "blue": {
    "logicOperator": "AND",
    "conditions": [
      {"subject": "water_level", "subjectType": "CONTENT", "operator": "GT", "threshold": 8, "unit": "m"}
    ],
    "description": "水位超过8m"
  },
  "yellow": {
    "logicOperator": "AND",
    "conditions": [
      {"subject": "water_level", "subjectType": "CONTENT", "operator": "GT", "threshold": 10, "unit": "m"}
    ]
  },
  "orange": {
    "logicOperator": "AND",
    "conditions": [
      {"subject": "water_level", "subjectType": "CONTENT", "operator": "GT", "threshold": 15, "unit": "m"},
      {"subject": "displacement", "subjectType": "CONTENT", "operator": "GT", "threshold": 30, "unit": "mm"}
    ]
  },
  "red": {
    "logicOperator": "AND",
    "conditions": [
      {"subject": "water_level", "subjectType": "CONTENT", "operator": "GT", "threshold": 20, "unit": "m"},
      {"subject": "displacement", "subjectType": "CONTENT", "operator": "GT", "threshold": 50, "unit": "mm"}
    ]
  }
}
```

#### 3.5.2 评估流程

```
evaluate(criteria, subjectValues)
  │
  ├── parseLevelConfig(json) → Map<"blue"|"yellow"|"orange"|"red", LevelConfig>
  │
  └── 从高到低遍历: red → orange → yellow → blue
        │
        └── evaluateLevel(config, subjectValues)
              │
              ├── logicOperator=AND: 所有 condition 必须满足
              ├── logicOperator=OR:  任一 condition 满足即通过
              │
              └── evaluateCondition(cond, value)
                    │
                    ├── CONTENT:  从 subjectValues 取 cond.subject 对应的值
                    ├── FUNCTION: 从 subjectValues 取预计算的函数值（如 AVG）
                    │
                    └── 运算符比较:
                          GT: value > threshold
                          GTE: value >= threshold
                          LT: value < threshold
                          LTE: value <= threshold
                          EQ: |value - threshold| < 0.0001
                          NEQ: |value - threshold| >= 0.0001
                          BETWEEN: threshold <= value <= thresholdMax
```

#### 3.5.3 主语类型

| subjectType | 示例                    | 说明                            |
|-------------|-----------------------|-------------------------------|
| CONTENT     | `water_level`         | 直接监测内容，从 subjectValues 取值     |
| FUNCTION    | `hourly_avg_rainfall` | 函数主语，需调用方预计算后放入 subjectValues |

#### 3.5.4 当前局限 (V3.1 TODO)

当前 `subjectValues` 仅包含当前到达的单个 attrCode 值。多指标判据（如"水位>20 且 位移>50"）需要从 IoTDB 回查其他指标的最新值。该功能标记为
V3.1。

## 4. 告警去重

**文件:** `AlarmDedupService.java`

### 4.1 持久计数 (persistCount)

```
persistCount=1 → 立即生成告警
persistCount>1 → Redis INCR 累加:
  key: alarm:pre-trigger:{criteriaId}:{hazardPointId}:{level}
  首次: SET + TTL
  未达阈值: 返回 false
  达到阈值: DELETE key + 生成告警
```

### 4.2 静默周期 (silencePeriod)

```
key: alarm:last-trigger:{criteriaId}:{hazardPointId}
存储: System.currentTimeMillis()
检查: now - lastTrigger < silencePeriod * 60_000L ms → 抑制
```

### 4.3 告警记录去重

```
createOrUpdateAlarm(record):
  阈值告警: SELECT WHERE criteria_id=? AND hazard_point_id=? AND status IN (1,2)
  综合告警: SELECT WHERE strategy_id=? AND hazard_point_id=? AND status IN (1,2)
  → 已存在: UPDATE trigger_count + 1
  → 不存在: INSERT 新记录
```

## 5. 告警记录

### 5.1 alarm_record 表

| 字段                            | 说明                        |
|-------------------------------|---------------------------|
| hazard_point_id/name          | 隐患点归属                     |
| device_id/sensor_id           | 触发设备/传感器                  |
| alarm_level (1-4)             | 蓝/黄/橙/红                   |
| alarm_type                    | THRESHOLD / COMPREHENSIVE |
| criteria_id/strategy_id       | 触发源                       |
| current_value/threshold_value | 测量值/阈值                    |
| first_trigger_time            | 首次触发时间                    |
| last_trigger_time             | 最近触发时间                    |
| trigger_count                 | 累计触发次数                    |
| status (1-4)                  | 待处理/处理中/已销警/误报            |
| resolved_by/at                | 处置人/时间                    |

### 5.2 状态机

```
  [告警引擎创建]
       │
       ▼
  ┌─────────┐   处置    ┌─────────┐
  │ 待处理   │ ──────→ │ 处理中   │
  │ status=1 │         │ status=2 │
  └────┬─────┘         └────┬─────┘
       │                    │
       │     销警/误报       │
       └────────┬───────────┘
                ▼
        ┌──────────────┐
        │ 已销警(3)     │
        │ 误报  (4)     │
        └──────┬───────┘
               │
         移入历史告警
    (GET /alarm/records/history)
```

### 5.3 alarm_record_log 表

每次状态变更记录一行：

- `from_status` / `to_status` — 状态转换
- `disposal_type` — 处置类型文本（开始处置/已销警/标记误报）
- `operator` — 操作人
- `disposal_result` — 处置结果
- `note` — 备注

## 6. 通知分发

**文件:** `AlarmNotifier.java`

```
@EventListener
onAlarmTriggered(AlarmTriggeredEvent)
  → dispatchService.selectEnabledRules()
  → 匹配: alarmLevel ∈ rule.alarmLevels AND alarmType ∈ rule.alarmTypes
  → 创建 alarm_notification 记录:
      SYSTEM 渠道 → status=2 (已发送, SSE 实时推送)
      SMS/EMAIL   → status=1 (待发送, 预留)
```

### 6.1 SSE 实时推送

**文件:** `AlarmStreamPublisher.java`

```
@EventListener
onAlarmTriggered(event)
  → CopyOnWriteArrayList<SseEmitter> 遍历
  → 推送 event: "alarm", data: { alarmId, hazardPointId, alarmLevel, alarmType, alarmMessage }
```

端点: `GET /api/v1/alarm/stream` (需 `iot:alarm-record:list` 权限)

## 7. 综合告警策略

**文件:** `ComprehensiveAlarmJob.java`

```
@Scheduled(fixedDelay=60_000)
executeCronStrategies()
  → SELECT * FROM alarm_strategy WHERE trigger_mode='CRON' AND is_enabled=1
  → 每个策略:
     ├── 直接绑定隐患点: alarm_strategy_hazard_point
     └── 监测类型兜底: SELECT DISTINCT dhp.hazard_point_id
                      FROM device_hazard_point dhp
                      JOIN device_sensor ds ON ds.device_id = dhp.device_id
                      WHERE ds.monitor_type_id = strategy.monitor_type_id
  → GrooveScriptExecutor.execute(scriptContent, variables)
  → 生成 alarm_record (alarm_type='COMPREHENSIVE')
```

## 8. 前端数据流

### 8.1 判据管理页 (AlarmCriteria.vue)

```
┌─ 监测类型 Tab ─────────────────────────────────────┐
│  getMonitorTypeList()                              │
│    → 左侧类型列表                                   │
│    → 选中类型 → getMonitorTypeDetail(id)            │
│      → monitorContents (供表达式编辑弹窗指标按钮)     │
│    → getCriteriaList({monitorTypeId, !hazardPointId})│
│      → 右侧判据面板                                 │
└────────────────────────────────────────────────────┘

┌─ 隐患点 Tab ───────────────────────────────────────┐
│  getHazardPointGroups() + getHazardPointPage()     │
│    → 隐患点树                                       │
│  选隐患点 → getBoundDevices(hpId) → 设备下拉         │
│  选设备   → getDeviceSensors(deviceId) → 传感器下拉   │
│  选传感器 → getSensorDetail(sensorId)               │
│    → monitorTypeId → loadMonitorContents(typeId)    │
│    → monitorContentId                               │
│    → getCriteriaList({hazardPointId, monitorContentId})│
│      → 右侧判据面板                                 │
└────────────────────────────────────────────────────┘

保存判据:
  1. 创建: POST /alarm/criteria { name, monitorTypeId, hazardPointId, monitorContentId, levelConfig:'<?>?' }
  2. 表达式编辑: ExpressionEditDialog → confirm → levelForm[key].expression
  3. 内联保存: buildLevelConfigFromForm() → 将 "水位(m) > 10" 解析为 JSON → PUT /alarm/criteria/{id}
```

### 8.2 表达式编辑 → level_config 转换

```
用户输入: "水位(m) > 10 且 小时变化 > 5"
       │
       ▼ (buildLevelConfigFromForm)
       │
level_config JSON:
{
  "blue": {
    "logicOperator": "AND",
    "conditions": [
      {"subject": "水位(m)", "operator": "GT", "threshold": 10},

```

## 10. 缓存键一览

| Redis Key                                | 用途            | TTL                    |
|------------------------------------------|---------------|------------------------|
| `alarm:criteria:enabled`                 | 启用的判据列表缓存     | 5 min                  |
| `alarm:pre-trigger:{cid}:{hpid}:{level}` | 预触发累加计数器      | persistCount × 2 × 60s |
| `alarm:last-trigger:{cid}:{hpid}`        | 最近触发时间戳 (静默期) | persistCount × 2 × 60s |
